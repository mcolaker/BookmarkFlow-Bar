## Source classes

### Application icons

`icons/icon16.png`, `icons/icon32.png`, `icons/icon48.png`, and `icons/icon128.png` are project-authored raster versions of the geometric `BF` application mark. They are source assets rather than screenshots. Their copyright is licensed under Apache-2.0; trademark rights remain governed by `TRADEMARKS.md`.

### Product tour GIFs

The five files under `src/assets/tour/` are project-authored captures of the real extension interface, generated with synthetic bookmark records by:

```powershell
node scripts/generate-tour-gifs.mjs
```

The generator uses Playwright for the extension session and FFmpeg for GIF encoding. It creates and deletes a temporary browser profile; it does not read the user's regular Chrome profile.

### Marketing and store media

The hero, promotional tile, and three store screenshots are generated by:

```powershell
node scripts/generate-marketing-assets.mjs
```

The script launches the unpacked extension in a temporary profile, seeds generic bookmarks, and serves its demonstration backdrop only from an ephemeral loopback server. The new-tab, page-overlay, and search-palette screenshots are real extension renders. The hero and promotional tile are fully local compositions incorporating those renders. All text, data, shapes, colors, and layout values are fixed in the generator; no random, time-dependent, remote, or user-profile input is rendered.

Browser and font rasterization can differ between operating systems or browser revisions. The digests below identify the reviewed files committed to this repository; regeneration on a different rendering stack may require an intentional digest update after visual review.

## Update procedure

When a tracked binary changes:

1. Regenerate it with the documented project script, or document the project-owned source and authoring method.
2. Confirm the required pixel dimensions and inspect the image at original detail.
3. Check that no personal data, secret, third-party logo, unlicensed media, or remote content is visible.
4. Replace the corresponding SHA-256 digest in this inventory in the same pull request.
5. Run the repository validation and public-tree checks before release.
